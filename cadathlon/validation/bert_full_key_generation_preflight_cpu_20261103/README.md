# Complete full-BERT key-store collector preflight

This evidence prepares the first of five actual file handlers, `client_key_generation`, for the unchanged common N131072/CD2/depth49/p60/dnum8 profile and all130 rotation indices. **No actual keys, encryption, model forward, server inference or full-model result are measured here.** The collector defaults to public preflight; actual generation requires a separately authorized `--execute` launch.

The reviewed worker calls the genuine first handler from an isolated copied source tree, verifies all startup/end source hashes, and relies on the actual key helper's security, complete-inventory, byte/hash/residue and readback gates. The parent checks the strict worker result and exact same source closure, and imposes no healthy-job timeout. Cancellation has120 seconds of graceful process-group cleanup before forced termination. Missing/corrupt/incomplete active process evidence causes the outer key workspace to be retained rather than removed. All INT/TERM/HUP signals are handled locally, with repeated signals shielded through cleanup and terminal publication; shared runtime collectors are unchanged.

Successful actual keys would remain only in an explicitly owned external workspace for subsequent size0 file stages. Failed known-reaped workspaces are removed by pinned inode/descriptor ownership. Neither raw keys nor private manifests/secret descriptors are copied into evidence. The worker exposes only public manifest metadata and verified private binding/permissions/file-count flags. This is first-handler readiness, not a claim that later handlers or a complete encrypted model have passed.
