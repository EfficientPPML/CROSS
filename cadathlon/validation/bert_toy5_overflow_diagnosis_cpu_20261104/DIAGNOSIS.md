The original BERT toy test5 remains a failed genuine TPU run: `OverflowError: int too large to convert to float`. The source-bound runner suppresses the exception traceback when producing its failure JSON, and no ciphertext, decrypted coefficient or key bodies are retained in this diagnosis. The exact throw site is therefore not established.

Public evidence records eight completed refreshes, three layer outputs (indices0–2), and both input and output security/device checkpoints. The output checkpoint is a returned/synchronized ciphertext with shape[1,2,256,512,40], NSD1 and scale6.8994011570896904e16 on TPU. The benchmark calls `session.decrypt(result)` after this checkpoint and before application metrics. The source chain is benchmark_session → ToyReferenceSession.decrypt → CKKSContext.decrypt_slots → _fast_decrypt_decode → _fast_decode. In the last function, `float(r) * scale_inv` and `float(im) * scale_inv` convert centered CRT integers before dividing by scale. Those two conversions are a strong candidate for the observed exception, not a proven trace.

The actual first40 public Q towers have a1096-bit product and a1095-bit half-product. Integer2**1024 lies within that centered CRT range but cannot be converted directly to binary64. Dividing that integer by the exact public binary64 scale first yields a finite value. At the other extreme, halfQ divided by the same scale exceeds binary64's finite range. This public geometry demonstrates two distinct conversion regimes without inspecting any actual coefficient.

The isolated candidate preserves the existing `float(integer) * scale_inv` expression for every representable integer. Only when conversion itself raises OverflowError does it use the exact binary64 scale's integer ratio and Python integer division. A genuinely nonrepresentable scaled value still raises OverflowError with a representation-specific message. No coefficients, ring, profile, domains, refresh count, source precision threshold, conjugate-symmetry test, FFT or application gate is changed. The candidate exists only in a diagnostic helper/AST overlay; it is not installed in any runtime.

Nineteen synthetic tests passed using the exact frozen _fast_decode and approximation-guard AST. CRT combination is replaced by an explicitly supplied synthetic integer list, and FFT is an explicit call-count seam; no decryption, secret context, HE/model backend, model or actual slot output is exercised; the preserved approximation guard uses NumPy CPU arithmetic. Tests establish bit-identical legacy conversion for representable integers, exact-Fraction agreement for recoverable huge numerators, unchanged1/32 approximation rejection for asymmetric huge coefficients, and continued failure for genuinely unrepresentable scaled values. A conjugate-symmetric real coefficient at index0 can legitimately pass the approximation guard after range-safe conversion; the tests preserve that behavior and make no magnitude gate. The initial18-test attempt incorrectly expected this symmetric control to fail; its17PASS/1FAIL source/log/XML are preserved, and v2 changes only that test assumption plus an explicit positive control.

Neither the synthetic candidate nor error classification establishes that the original encrypted coefficients would become valid. It can improve normalization robustness or expose a later existing precision failure; it is not an HE precision repair and cannot convert the recorded failed run into a pass. A future separately authorized checkpoint diagnostic would be needed to identify the real coefficient/refresh failure, preserving the original decoder and application gates.
