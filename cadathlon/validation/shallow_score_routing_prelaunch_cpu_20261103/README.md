# Two-level score-routing prelaunch checks

The isolated candidate passed **160 backend-free tests** (1.24s pytest, 1.4167s collector) and an actual-ring public CPU preflight against the same **99 unchanged source files**. The separate encrypted experiment was running at archival time; this is not a numerical ciphertext result or a promoted runtime change.

The route compacts twelve head anchors with twelve public diagonal terms in one weighted sum, then places each of sixteen rows at its public key position with sixteen terms in a second weighted sum. Each weighted sum performs one actual composite rescale. The inverse reverses these two operations. Compared with the previously measured nine-level bitwise route, this plan uses two levels per direction at the cost of more rotations and simultaneous ciphertext operands. It does not establish a speedup.

All 128 key-tile/offset combinations pass independent ideal gather/scatter checks over all 65,536 slots, including hostile nonanchor values and a separate hostile-input inverse. The input and its metadata remain unchanged in these ideal tests. The planned encrypted proof uses tile7/offset15 and both gains1 and1/8, capturing all four stages per gain at levels4/3/2/1 from input level5. The fixed ciphertext gate is 1e-6 over all 524,288 decoded checkpoint values, after server computation completes.

The actual public profile is N131072, CD2, depth5, Q12/P3, dnum4 and scale6.8994e16. Actual log2(QP)=430.5911 satisfies the library's 128-bit security ceiling, and P coverage passes. The two directions need 54 direct rotation keys for this tile/offset; estimated public material is 3,472,883,712 bytes plus a separate4GiB storage margin. These are raw storage estimates, not process memory bounds. The two-gain circuit plans108 rotations,112 public multiplications and8 rescales in total.

Independent review identified two API/lifecycle issues before encrypted launch. The helper now explicitly rejects bound-aware owners: deleting stale bounds without propagating a sound new bound would otherwise break a later operation. The driver now preserves cleanup-only `KeyboardInterrupt`/`SystemExit` after attempting all releases and publishing the report; five focused tests cover cancellation and primary-failure preservation. Earlier source-bound preflight/tests are retained under v1, while v2 contains both fixes. `tests_initial.*` is an earlier154-test log without a separately captured exact source snapshot and is not the final evidence.

The proof driver uses separate client/server objects in one isolated CPU process, with class-wide codec guards during server computation, both key-generation aliases guarded, post-server validation and owned key cleanup. This is not an OS sandbox or a production file boundary. The helper supports the explicitly declared no-refresh `CompiledArithmetic` contract only. No full attention, softmax, refresh, BERT model, TPU or calibration result is claimed.

`archive_verification.json` records independent member-by-member verification of all four source archives and the authoritative final test exit. The archives contain source only; retained loose files are public metadata and logs. No keys, ciphertext payloads or private arrays are included.
