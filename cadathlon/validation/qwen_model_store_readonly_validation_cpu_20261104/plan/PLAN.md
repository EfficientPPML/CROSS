# Readonly Qwen model-store validation entry proposal

This is a source-only implementation plan around the accepted 29-source model-stage component. It contains no actual entry, grant, current-store inventory, body validation, test execution, or model/HE operation. The separate 38-source/48-test preparation retains all 29 parent bytes and has its own owner and authorization. No export, calibration, heldout, token, key, or ciphertext body is selected here.

The smallest actual producer is one fresh, root-owned Python process. It authenticates a separately reviewed source closure and readonly grant, validates the existing exported stores, retires its file/mapping owners, and publishes a bounded public report. Root supplies a separate outer receipt only after the actual process returns and is reaped with its process group absent. No worker/collector fanout, backend context, fresh 4.768 GB export, or duplicate parameter store is needed.

## Selected sources and narrow additions

Preserve the accepted 29 files byte-for-byte, including `model_admission.py`, the expected-identity overlay in `qwen_public_parameters.py`, `model_store_validation.py`, and all 12 public metadata files. The existing recording function and its disabled actual factories remain recording-only. A new actual module must call the fixed `open_identity_bound_parameters` directly after its source/grant gate; it must not call `validate_store_for_recording` with real files and relabel that result.

Proposed additions are `model_entry.py` (stdlib bootstrap and terminal boundary), `model_validation_process.py` (fixed actual traversal, lifetime and report), `model_validation_grant.py` (pure grant/public-binding gate), `model_output.py` (bounded reads and fresh evidence publication), and reviewed static role/dependency/protected-path metadata. These names identify proposed work, not an implemented or final source inventory. The inherited test files, key loaders, server/client glue, arithmetic, historical collectors, and generic `reused_client_io` read/write/archive/Finalizer helpers are unselected.

The source references pin three existing reviewed patterns: checker141's `entry.authenticate`/verified-byte loader and exact-int terminal-status boundary; its `freeze_io.Output` inode-bound exclusive publication; and `checker_process.supervise` cleanup/publication ordering. The actual source closure must declare the adaptations, rather than copying the entire checker runtime. In particular the old checker helpers use `_qwen_observer_*` exception markers. Model29 uses shared `cleanup_origin`4543 (`_cross_toy4_*`, `mark/select/protect_body`) with `qwen_finalizer`46e656. The new bootstrap's preimport bookkeeping and output/process helpers must use that one accepted policy. Copying the old observer marker names or its `choose/mark_cleanup` API unchanged would break cleanup-origin continuity.

## Entry before any borrowed body access

The intended CLI has one actual readonly role and requires external source-map path/digest, external grant path/digest, and a fresh evidence-output path. A help parse may return normally outside actual dispatch. Every source check, import, grant check, acquisition, validation, cleanup and final publication is inside the reviewed terminal boundary: only a normal exact integer 0 or 1 can become that status; any escaping `BaseException`, malformed return, or diagnostic-printing failure yields infrastructure status 70. This validation has no scientific failed-result admission: only normal zero can qualify. Do not infer normal completion from empty stderr.

Start with `-I -B`, no preloaded candidate/NumPy/backend modules, and a stdlib bootstrap. Authenticate the external source-map SHA and require the raw map to equal canonical sorted compact JSON with one newline, the same encoding accepted by `ExpectedModelPins`. Require the exact typed ordinary-file tree, no extra files/directories or symlinks, canonical resolved source paths, independently checked `__file__` and spec origins including `PathLike` aliases, and the exact required module inventory. Proposed bounds are 512 files, 8 MiB per member, 32 MiB total, and 1 MiB for the source map. Do not inherit the checker's selector-assessment size exception. Import local helpers from those verified bytes; reauthenticate current bytes/origins at termination. There is no model-import enable switch.

Authenticate grant bytes and its pinned root prelaunch review before importing the NumPy-backed reader or opening parameter directories. `grant.schema.json` is a proposed closed schema, not an issued grant. Its expected-store descriptor names canonical immutable bytes, capped at 2 MiB, that pass accepted `ExpectedStoreIdentity.check`. The grant binds the fixed model/content/catalog, complete canonical producer map, archive hash, selected dependency/policy hashes, exact source and evidence paths, and this one readonly role. Root's prelaunch review independently authenticates archive bytes/members and the known historical export evidence using their original schemas; neither a digest alone nor the pure model gate claims to inspect an archive. Reuse the actual reviewed preparation/root-receipt shape when it exists, rather than inventing historical receipt fields. The externally trusted grant pins those exact review bytes and independently binds source/archive/store expectations. A new mandatory readiness schema is unnecessary.

The launch and terminal reviewers remain the external trust boundary. Preparation may retain `actual_execution_enabled=False` while the new role accepts only an independently pinned, explicitly scoped external grant. This is a new grant-capable boundary; the accepted 29 actual factories remain disabled. A completed scientific calibration freeze is not required to authenticate learned file integrity, and this validation does not create one.

Before reading any supplied role file, reject lexical and resolved overlap with the selected source tree, borrowed stores and protected token/private/key/CT/outcome roots. Static protected paths must derive only from already reviewed public metadata; dynamic grant/store paths supplement them. Output and its parent must be canonical, disjoint in both ancestor directions from every protected/input/source/grant path, and fresh. Metadata lookup during path validation is distinct from file-body access. Grant and expected-store metadata stay outside borrowed data roots. Root has not yet authorized even the new current-store inventory acquisition.

After grant admission, install a readonly audit policy admitting only the fixed 197 NPY names and one gamma NPZ, with those held descriptors, plus authenticated source/dependency/public-role reads and fresh owned evidence writes. Reject data-body opens elsewhere, writes/chmod/removal in borrowed stores, network and child creation. Directory-relative and fd reads must be attributed through retained owners, not merely matched by a relative basename. Allow only the required NumPy host import closure; forbid JAX/JAXlib/jaxite_word, Torch/Transformers, TensorFlow/Flax/torch_xla, safetensors/tokenizers and libtpu. Pin the four already selected NumPy source files and verify genuine loaded origins before/after; these four hashes do not assert complete provenance for every installed NumPy binary. The separately reviewed runtime/dependency policy must state that scope honestly.

## Expected identities and complete traversal

Root first performs a separately authorized metadata-only acquisition of the exact three borrowed directory identities and 198 selected file states. It uses lstat/scandir metadata for known catalog names and existing public descriptor hashes, with no parameter file open/hash/header/read or broad directory harvest. Record `dev/inode/mode` for roots and `dev/inode/size/mtime_ns/ctime_ns/mode` for files; repeat the root/path metadata checks around acquisition, without claiming an atomic body snapshot. The later held reader must reject any changed expectation. No export or permission change is needed. Root pins the canonical `ExpectedStoreIdentity` bytes. This metadata is an expectation, not an integrity result, and any change requires explicit renewed admission rather than an in-process resnapshot.

The actual process rederives `ParameterCatalog` from the 12 authenticated public metadata files and compares its complete four-field representation with the fixed aggregate. The existing hook checks each held/named root before any parameter file, and each held/named file's exact external state before its first hash/header/mmap. It must remain active throughout the traversal. No path-stat followed by a newly unbound factory substitutes for these acquisition checks.

Capture the original owner and its `check/matrix/gamma/readback/close` accessors immediately, with `close` first. Retain immutable intent/catalog/store/source snapshots and use captured originals for cleanup; callback-writable fields never define the retirement inventory. Call all 198 sorted logical matrix names, require exactly 197 physical leases, and verify that the tied embedding/head alias refers to its one original physical descriptor. Visit all 113 sorted gamma names; the first gamma access already authenticates the exact bounded container/member inventory. Each returned view is dropped within its individual operation. Do not retain arrays in reports, callbacks, exception diagnostic payloads, or an output collection.

This readonly validator is not an entered arithmetic consumer. It constructs no context or compiled owner and must not fabricate `consumer_entered/consumers_retired` events. Its returned temporary views are gone before backing retirement. Capture the observed root/file metadata while the original descriptors are live and compare it to the external expectation; do not populate the report merely by echoing the grant. Final original readback rehashes every loaded matrix file and the gamma container. The selected owner also readbacks during close; that cost is inherited and is not a reason to remove checks in this minimal successor.

Use shared `Finalizer` and signal scopes to attempt original readback, mapping/file/root closes, ownership checks and source postchecks on every outcome. Shield construction/entry failure must still execute cleanup. Protect genuine body identity before cleanup can rethrow it; cleanup-only cancellation keeps priority over ordinary cleanup failures. Detach-before-close and failure quarantine remain as selected; an uncertain close cannot be retried or reported successful. No borrowed store is retired, deleted, chmodded or rewritten.

## Report and terminal admission

The positive report must match the existing closed `qwen-model-store-validation-v1` contract exactly: all 198 logical/197 physical/113 gamma counts, 4,767,875,072 matrix raw bytes, 524,288 gamma raw bytes, exact model/aggregate/catalog/grant/source/archive bindings, three roots/198 observed file records, all integrity/readback/cleanup/signal/source flags true, no error and no audit denials. It claims parameter-body validation only. Every new export, model forward, context/key/CT/token read, coefficient selection and scientific-calibration claim stays false.

An actual process builds this success document only from completed direct operations. It does not reuse recording counts as evidence. A failed or interrupted attempt may write a separate, non-admissible failure document with completed visits and monotone read state: before owner acquisition no read is claimed; after entering an operation that could read, an unobserved outcome is explicitly unknown; only completed validation supports `parameter_body_reads_performed=True` with full integrity. No unconditional pre-call success flag or falsely certain no-read claim is allowed. Failures never match the positive gate schema.

Finish body cleanup and signal restoration, then reopen only the original evidence directory inode to publish canonical `report.json`. All files are fresh exclusive names, mode0600 within owned0700 output, bounded and fsynced/read back; preserve partial evidence on failure. The referenced checker Output performs exclusive writes/fsync and inode/size checks but does not itself reread content. Declare a small output-only adaptation: use the original fresh file descriptor for bounded content readback, verify its exact bytes/hash before detaching and closing it, and fsync the held evidence directory. Adapt cleanup to shared4543, including final publication close. These writes touch only new bounded public evidence. A report cannot certify its own last close. Any escaping late error becomes status70; the independently observed exit must still be zero for admission. Root reauthenticates current sources, archive members, report/store expectations, PID/PGID, direct wait and known group absence before issuing the existing outer/root schemas. No directory or stderr observation substitutes for direct ownership/reaping.

`authenticate_model` remains the unchanged pure bytes/pins consumer. Root supplies the final report, outer and root-review hashes only after they exist; it also supplies the independently reviewed future consumer map. Model-validator producer identity, future server/client consumer identity, request/response producer identity and cryptographic context identity remain distinct. A later actual server/client must call `require_admitted` and compare model identity before entering its key loader. The content-derived model_id remains independent of those source/grant/process hashes. Existing original-embedding APIs remain unchanged; this work adds no tokenizer or token-lookup requirement.

## Bounded resource proposal and next step

The base lifetime is 3 directory descriptors + 197 matrix-file descriptors + 1 gamma-file descriptor = 201. Budget another 197 descriptors conservatively for mmap implementation ownership, plus 32 for sources, grant, output and runtime, giving a 430-descriptor planning ceiling and proposed minimum soft limit512. The mmap allowance is a conservative budget, not a claim that every platform duplicates a descriptor. Check the actual process's open-descriptor baseline before grant and reject insufficient headroom; do not change system limits implicitly.

There are 197 readonly mappings of the existing files. Their mapped extent is the sum of externally admitted file sizes, roughly the 4.768 GB raw payload plus headers. This is virtual mapping/file-cache exposure, not a measured peak RSS and not fresh disk allocation. The existing finite scan has at most131,072 values per boolean check; streaming hashes use1 MiB chunks; gamma container/decompressed content is capped at4 MiB and retained gamma raw values total524,288 bytes. A conservative future grant can require available memory at least the exact mapped extent plus512 MiB and a fresh128 MiB evidence reserve. This is a proposed capacity floor, not a performance or memory measurement. No fresh parameter-copy reserve is charged. Source archive remains an externally admitted public artifact; evidence need not duplicate its bytes.

One CPU process on proposed lane120–123 with host numeric thread counts1 is sufficient; exact affinity/environment and available resources belong to the later reviewed grant. No timing benefit is claimed, and no healthy timeout is proposed. The next step is root review of this source-only selection/schema and then a separate implementation decision. Actual body inventory, implementation tests, actual readonly launch and downstream server authority are all still absent.
