# Pure actual client authority boundary — source checkpoint

This successor authors public-evidence validation only. It neither implements nor
imports an actual client loader/backend/reader/process. All actual entry stubs
raise immediately. No candidate module, NumPy, backend or test is imported/run
during this preparation. No actual ModelAdmission is instantiated here, no key
readiness exists, and no grant is issued.

The exact28 parent is the separately admitted writer-pin successor f30d07f8,
including keygen_authority95e26 and model_admission60bb unchanged. Its one changed
minimum writer pin is96a200. The original28 d67a and39-test proof remain intact.
Two parent maps record that history. Inherited DESIGN/status/provenance files
remain historical bytes; this document describes this new source checkpoint.

## Conditional role and phase APIs

`authenticate_conditional_role(intent, model, grant_bytes, *, expected_pins)`
accepts exact ActualKeygenIntent and independently trusted ExpectedRolePins.
It calls unchanged `require_admitted` for the exact future client consumer map,
then compares all five model-proof pins. It checks actual-client required module
names and93 fixed existing source prerequisites, complete canonical map digest,
archive/readiness review, intended generation source/archive/intent, named role,
entry and externally pinned policy hashes. Source hashes for new actual modules
remain external; these are not fabricated or equated to this pure source map.

Conditional grants have no immediate body permission. Their closed conditions
require later independently admitted generated keys, a phase-instance grant,
current store checks, and actual dependency/capacity checks. The source root is
pure canonical metadata, not an opened/verified directory. A conditional grant
can bind the already concrete generation intent and source without referring back
to the later generation-grant digest. No digest cycle or authority28 exception
is introduced. Named input/output roles may share one reviewed client source map.

`authenticate_phase(conditional, readiness, request_bytes, grant_bytes, *,
expected_pins, server=None)` reauthenticates both retained chains. It requires
the original generation intent, exact generation map/archive, and keygen's
recorded four-field role evidence to match the conditional grant. Client and
generation ModelAdmissions have different expected consumer pins but must bind
the same four original model proof bytes. ExpectedIds comes only from rechecked
GeneratedKeyReadiness, not incoming manifests. The full PublicContract request
identity and public key manifest are authenticated in memory before any future
private/key/context operation.

Closed phase grants bind independently supplied generated-key proof pins and
retained root/manifest identities, exact request digest, role policies, input
descriptor and two fresh output descriptors. Input is either an original
float64[1,S,1024] bounded NPY descriptor or a complete38 response descriptor with
the separate server evidence hashes. Output leaves must be mutually disjoint and
outside key/model/source/input scopes. Existing parents may contain protected
siblings. These pure comparisons do not perform lstat/open, prove ownership or
reserve capacity; the actual process still needs original-FD comparisons and a
source-bound protected-path policy before its first permitted I/O.

`PhaseAdmission.expected_ids()` reauthenticates before returning client-only
ExpectedIds. Every returned object's `execution_authorized` is False. This is
not a filesystem capability and does not replace actual process admission.

## Independent actual server envelope

`authenticate_server(public, model, readiness, request_bytes, input_digest,
response_bytes, inner_report_bytes, inner_outer_bytes, envelope_bytes,
outer_bytes, root_review_bytes, *, expected_pins)` is pure and uses no NumPy.
It reauthenticates an independently repinned server ModelAdmission, generated
keys, full request/response schemas, and the existing inner373 report/outer
declarations. The inner producer-source field remains the request-producer
identity. It is never used as the actual server execution-source identity.

The additional closed envelope binds a separate actual server source map/archive,
server grant/readiness review, scientific-authorization digest, full source
before/after maps, key/model evidence, request/response/inner-report links,
actual process IDs, exact cleanup/security checks and no audit denials. The
independent outer must report normal exact zero, reap and group absence for the
same IDs. The externally pinned root review attests source/archive/current-response
and scientific-authorization checks, while denying client execution by itself.
No scientific oracle is reconstructed here: that independent authorization is
an explicit trusted-root prerequisite, not a newly inferred calibration PASS.

The consumer phase requires the same retained readiness/request and exact server
evidence hashes. ResponseFiles must still authenticate all38 payload bodies on
held original descriptors before the private loader. These pure modules read
only public metadata bytes; they do not perform those payload checks themselves.

## Source selection and limits

`client_role_source_pins.py` contains93 exact existing prerequisites derived from
the admitted373/core/common/cleanup/parser selection and authority28-v2. The
14 named actual implementation modules are required in a future independently
trusted complete role map. Several do not exist here. The current pure tree
therefore cannot pass as a complete actual role implementation. A future allowed
overlay must receive an explicitly reviewed new minimum-pin source successor;
silently changing these pins is not an activation path.

The source resolver must have one PublicContract/key/model/authority/parser
identity. Actual runtime resolution remains ROOT, runtime/common, runtime and
an explicit flat/package core alias map; historical/test/provenance copies stay
unreachable. The root-only pure imported modules and exact existing93 source
origins are enumerated in client_source_selection.json. This is a precise source
selection obligation, not a proof that future backend imports are ready.
