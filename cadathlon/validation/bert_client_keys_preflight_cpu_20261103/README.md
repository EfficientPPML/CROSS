# Full-BERT client-key helper: public/mocked preflight

The isolated helper implements the actual production key-generator calls for the fixed N131072/CD2/depth49/p60/dnum8 profile and the complete ordered 130-rotation union. This evidence executes metadata, storage and lifecycle tests with tiny mocked producers. It does not execute actual key generation, encryption, a CKKS context, or HE.

The real `qp_is_secure` and `assert_p_coverage` predicates passed for Q100/P14 (log2(QP)=3402.080255733439). Their imports initialize public CPU constants; this was explicitly permitted after an initial backend-free guard blocked the import. Both real predicates precede `_crypto` and every production key-generator call. The raw Python-integer secret remains unchanged for relinearization/rotation generation; validated uint32 conversion applies only to serialized storage, avoiding secret-square overflow before modular reduction.

`generate(public_keys, client_private, *, profile_bytes, plan_bytes)` requires two fresh destination directories. Public/private trees have pinned owned handles, parent-path replacement checks and attempt-all cleanup. Secret material is created only in the private 0700 directory with 0600 files. The public context digest binds fixed checkpoint/config/candidate/profile/rotation-plan identities and the complete key-array inventory. Bounded NPY headers, exact shapes/dtypes, hashes and canonical residues are checked before stored arrays are accepted. The helper contains no client-input or model-forward code. Server/client context loaders are separate work.

The full profile requires 263 public arrays totaling 125380329472 raw bytes, plus 52428800 private-key bytes. The storage reservation including bounded headers and margins is 126508630016 bytes (about 117.82 GiB). This excludes working generation buffers, context/control tables, model weights and ciphertexts; it is not a peak-memory measurement or a key-generation timing result.

The final source-bound run passed 42 tests in 2.42 seconds, with 40 source/public-input files unchanged and every tar member read back. Archive SHA-256: `85dd7e6d1db17e6d380fb9e6b154c8d803331bb05fbd5c8404399314b6b0ec7f`. The owned test subprocess and collector exited 0 and were reaped. The first development snapshot preserves 32 passes and two failures: the blocked public-constant backend import and an overly broad test substring that matched the public `secret_distribution` field. That snapshot was captured after terminal completion, before edits; it had no startup source archive. No failure was hidden and no actual key material was created.

This directory contains sources, public parameters and test evidence, with no mock key-array files or real keys. Run `python verify.py` for offline source/resource/security consistency checks.
