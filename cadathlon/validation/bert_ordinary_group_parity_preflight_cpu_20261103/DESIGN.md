## Fixed future circuit

At each actual level 49 and 25, the same stage3 tile0 is used for three independent serial groups:

- Head shifts: `(0, 63, 126, …, 693)`, 12 requests, 11 nonzero.
- Local-key shifts: `(0, -16, -32, …, -240)`, 16 requests, 15 nonzero.
- Edge semantics: `(0, 63, 63, -16, 0)`, 5 requests, 3 nonzero.

All 26 distinct normalized nonzero shifts are in the authenticated existing rotation inventory. Zeros alias the original object; duplicates execute separately and preserve order. Across both levels this gives 66 full-array comparisons, 58 nonzero comparison pairs, eight zero aliases, 116 actual per-key completions (58 original plus 58 grouped), and six shared decompositions. The worker requires the group's reported mode to be `digits`, so an ordinary fallback cannot masquerade as successful shared-decomposition evidence.

L25 is obtained once from the original L49 value via `ctx.he_level_reduce[49,25].level_reduce`. All ordered Q-prefix payload words, scale, NSD, layout and precision are checked; no scale relabel or rescale is used. Each output is compared bit for bit against the original per-key `CompiledArithmetic.rotate`, using the same initialized keyless context, low-memory policy and dispatch-cache policy. No decryption or numerical oracle is involved. A group tuple is released before the next group, and each baseline result is released immediately after its comparison.

## Logical storage and supported scope

The owner limits are 16 results, 2 GiB logical result payload and 512 MiB logical digits. At L49 the largest requested result group is 15 new arrays = 1,500 MiB; digits = 456 MiB. At L25 they are 780 MiB and 132 MiB. One baseline result, the original source, controls, compiler/executables, converted key pair, host key maps, allocator overhead and failure quarantine are outside these caps. These are not measured RSS/HBM or a memory-fit promise. No keys are stacked. Only one converted key pair is live in each serial completion; already-completed group outputs remain bounded until comparison.

The shared path requires exact standard Barrett, sub-31-bit primes, CD2, uint32 payloads, one device and ordered max-Q-based partitioning. It preserves the original per-part product accumulation and ModDown/c0/map operation order. Immutable JAX arrays and an authenticated keyless no-write source are API prerequisites. Unsupported arithmetic may use original per-key completion only under the same source/keyless/result limits, but this fixed genuine proof requires the supported digits path. Result-budget failure rejects before work.

## Evidence and limitations

Source discovery enumerates only fixed runtime/joined/base/server_inputs trees plus root Python/JSON files. Nested proof directories cannot become source inputs. The collector retains every failure, preserves primary cancellation, uses the reviewed signal/terminal helpers, has no healthy deadline, and never deletes borrowed key/model/upload workspaces. The upload directory is bound by a held descriptor; concurrently created stage4 sibling outputs are permitted.

The first development profile test omitted explicit CPU selection and backend initialization was rejected because the TPU was busy. Its exact source archive and failed log are preserved. The public plan now rejects a missing `JAX_PLATFORMS=cpu` before backend-dependent imports. No context, key, ciphertext payload or encrypted arithmetic ran in that failure. Subsequent checks use explicit CPU168–171.

This is not a new secure-HE result, an accuracy test, a full-model result or a speed comparison. The existing public-array group proof and independently running prepared-key parity remain separate evidence. Source-bound review and authorization are still needed before any genuine group execution.
