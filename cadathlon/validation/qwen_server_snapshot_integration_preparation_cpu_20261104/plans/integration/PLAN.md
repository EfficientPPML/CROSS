# Retained server admission integration — source-only proposal

The proposed successor replaces repeated full packet/scientific validation in the runtime/backend checks with the exact retained snapshot guard `8790711a…`. It keeps complete public proof admission and boundary revalidation, live file identities, loader ownership, security checks and all body-access transitions. The selected complete-capacity gate continues to deny unconditionally. This plan grants no execution and changes no current source.

`source_refs.json` pins the inspected source slices. All fourteen pure helper modules imported by the held guard are byte-identical to their counterparts in the current server tree. The guard's thirteen explicit object types and fields therefore need no schema adaptation for this integration. Its source must be copied literally, not replaced with a generalized memoizer. The current server tree is a development parent; a future successor must capture its complete exact parent inventory before editing, preserve it, and declare every overlay. This plan only pins the inspected source slices, not a new full387 proof.

## Present repeated work

* `ServerBackend.check()` calls `_runtime(runtime) → RuntimeAdmission.check() → control('check') → packet.check()`, and then independently calls `phase.check()` again. `ServerPacket.check()` itself reauthenticates its phase and reconstructs the complete packet, including scientific proofs.
* The loader's bound `map_array` calls the backend and runtime scope checks for each public array. This is on the selected 335-array path; the exact nested invocation count has not been measured. It also retains the genuine reader's directory, header, shape, hash, residue and ownership checks.
* `ActualServerDependencies.check()` calls `phase.expected_ids()`, which invokes full `phase.check()` before deriving generated key IDs. Factory checks and public-key admission reach this route too.
* `publisher()` and report construction access `phase.input_digest`; that property also invokes the full phase validator. These immutable metadata values need no repeated scientific reconstruction after a retained graph is admitted.
* Current `source_check()` combines complete source reads, origin checks, `packet.check()`, environment/audit/core checks, `runtime.check()`, and rereading all independently pinned public proof files. Passing it directly to `capture_admitted` would introduce recursion: guard → source_check → runtime.check → guard. Avoid that edge explicitly.

This is a call-graph diagnosis, not a timing or speed claim. Core source checks, PublicContract/key-manifest checks and live readers have their own costs and remain selected.

Do not integrate the separate device-capacity component in this change. No mathematical, HE, decoder, policy schema, key reader, key loader, file stage, publisher or pure-validator body change is proposed.

Keep `admit()`'s public path/memory/pin checks, actual public-file reads and full `authenticate_packet()` call. Keep the current full checks at entry, post-import, public-key/body transitions, after the stage and during terminal cleanup; these are finite process boundaries, not per-array checks. The guard capture adds its own full packet validation once at capture, as its unchanged implementation requires. This proposal does not promise only one full validation in the whole process.

After full admission, bind the guard module and its pure helper closure to the external selected source map and exact canonical file/spec origins before invoking its original `capture_admitted`. Capture the original module/spec, class descriptors and `capture_admitted`, `AdmissionSnapshot.check` and `retire` function/code/default identities. Retain and invoke the original bound check/retire accessors, comparing current exports/descriptors before use. The guard does not bind its own module for the caller; this remains an explicit process obligation.

Separate three checks:

1. `binding_check()` is the guard's nonrecursive callback. It checks selected guard/pure-helper/process/backend/entry binding source bytes and canonical origins against immutable expected bytes, original module/spec/function/class identities, the original source/origin callbacks, and the exact environment. Its bounded selected-source list is explicit and derived from the existing map; it is not a glob or caller-controlled path list. It may use the unchanged entry origin checker to reject unknown aliases. It must not call the guard, RuntimeAdmission, packet/phase/public validators, audit body-transition methods, capacity, or a backend/reader. It never reads proof bodies or borrowed data. Hashing this bounded Python source closure on each check is acceptable initially; replacing it with metadata-only source caching is out of scope.
2. `runtime.control()` invokes the captured guard check, then retains the existing `core.check()`, original audit method/wrapper/state checks, sticky denials and read-transition state machine. The guard is only an immutable admitted-graph check, not permission to read. Use the original packet/runtime/core/audit objects and original callback identities; reject equal replacement. Any runtime binding/state failure becomes sticky and leaves original references held for process cleanup. Do not allow a caught rejection to restore a usable runtime.
3. `full_boundary_check()` retains the old complete source inventory/bytes, origin/environment, full packet and pinned public-file reread checks. Capture full-validator accessors before callback work, invoke them between guard checks, and keep core/audit checks at their existing valid lifecycle points. It may call the now-bounded runtime check; its callback must not point back to `full_boundary_check`. Full scientific replay remains required at terminal. Terminal filesystem and source rejection cannot be replaced by an in-memory snapshot success.

The callback source closure must be listed mechanically during implementation, including all fourteen pure modules and the guard, process, backend, entry and directly used binding helpers. It is independently pinned from the successor map, and current exports are compared before invocation. Frozen dictionaries or dataclasses alone are not an authority token. Original expected-map/blob/record objects and a canonical immutable representation of their bindings are retained; replacement or mutation is rejected. No global packet hash→PASS table or cross-run cache is introduced.

No PASS return occurs before this last step; entry status70 and the separate outer receipt remain mandatory for late failure.
