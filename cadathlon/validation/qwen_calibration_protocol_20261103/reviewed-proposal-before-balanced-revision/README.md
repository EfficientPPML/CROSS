# Proposed Qwen calibration repair, before model measurement

This is a public, native/plaintext-only protocol proposal. No calibration model forward, approximate trajectory, key generation, HE operation, or TPU execution has run under it. Root review is pending. The archived failed validation-domain coverage and all its gates remain unchanged.

The fixed corpus contains 32 authored topics with three framing variants: 96 unique prompts in each exact token-length bucket 8, 16 and 32, giving 288 prefill contexts. Sixteen fixed calibration prompts also seed four-token decode. These decode seeds deliberately overlap calibration prefills; they are not independent validation. Paragraphs have 52–107 tokenizer tokens before truncation. There is no padding or artificial repetition. Token sequences are unique within each bucket and are disjoint from all 56 previously frozen validation input sequences. Only that input manifest was used for collision checking. The generated texts were not chosen using validation activations, errors, logits or output tokens.

`protocol.json` freezes the domain slack, analytic targets, candidate degree order, fallback rules, numeric/model gates and failure handling before any new model observation. Candidate ranges come only from native/exact calibration inputs and, for a later calibration-only candidate, earlier approximate calibration trajectories. Coefficients approximate analytic functions; output errors and native logits are not fitting targets. At most three candidates total, including the first, are allowed. Each manifest must be frozen before evaluating its approximate trajectories. Only the first calibration-passing candidate may be evaluated on the unchanged validation workload. Any stopped trajectory has partial coverage, not a full accuracy result. After validation is measured, it cannot feed a further candidate under this protocol.

A complete native/exact calibration pass has 416 contexts: 288 prefills, 64 teacher-forced decode contexts and 64 free-running decode contexts. Teacher forcing uses original native preceding tokens; free running uses the evaluated circuit's preceding tokens with the native oracle evaluated on that same context. All 151936 final logits are checked, and the 28-layer RMS/QK-norm/SiLU/causal-normalization/final-norm inputs must be instrumented. Approximate calibration and subsequent validation must retain every applicable original operator, block, full-logit and token-agreement gate. This is not a hidden benchmark calibration publisher or a language-task accuracy study.

`reciprocal_schedule.json` supplies every public causal count K=1..32. It preserves the existing C1 reciprocal graph, with initial exponential-mean interval [0.5,2] and each squared-probability denominator interval [0.5/K,2]. The initial estimate and first affine coefficients are binary64 values. Exact rational endpoint/vertex analysis bounds the complete first residual, then directed 100-digit decimal squaring chooses the smallest count meeting 1e-12. Counts range from 6 to 11; inactive inputs use the public interval midpoint. This certificate covers subsequent exact-real Newton arithmetic only. It does not establish later floating-point error, positivity/mass after CKKS or refresh, or composition with the polynomial exponential. Full-trajectory domain checks remain required. No C32 or integer-affine optimization is silently introduced.

The separate native-algebra normalization bound is as large as 6144 (power-of-two cover 8192) across Qwen, versus the prior Q/K-only observed maximum about 486.8. Those bounds are not polynomial/CKKS guarantees. This protocol makes no claim that bounds 16/64, an existing refresh profile, a particular common ring, or any encrypted error budget suffices. Refresh placement and scaled conditioning require separate numerical evidence.

`model_pins.json` records the existing pinned Qwen3-0.6B revision and seven asset hashes. The tokenizer preflight verifies the four tokenizer assets before and after use, the selected proposal sources before/after, exact lengths and disjointness, and absence of JAX/HE imports. It does not instantiate or hash-load the model checkpoint; a future model collector must verify all seven assets before and after, freeze its complete selected source closure, and preserve every failure. Installed tokenizer/library versions are recorded, not an entire OS or Python-binary closure.

Reproduce the public checks with the existing offline environment:

```sh
OPENBLAS_NUM_THREADS=4 OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 taskset -c 140-143 /tmp/cross-pretrained-validation-env/bin/python check_inputs.py
OPENBLAS_NUM_THREADS=4 OMP_NUM_THREADS=4 taskset -c 140-143 /tmp/cross-pretrained-validation-env/bin/python -m unittest -v test_protocol
```

`initial-tokenizer-preflight/` preserves the earlier successful tokenizer check before pins, reciprocal linkage, stopped-coverage wording and the normalization-bound note were added. Corpus/tokenized input bytes did not change. `verification.json` describes the final proposal snapshot, and `verify_archive.py` verifies it without importing a model or numerical backend. Source archives contain scripts and public JSON only; there are no model weights, private inputs, keys, ciphertexts or hidden activations.
