# Isolated ranked BERT gates and batch orchestration checks

Preparation only. This successor adds all-nine public fixture/reference gates,
ordered N request/response readbacks, a client-only bounded reference reader,
ranked output/receipt acceptance and a future producer-proof schema. It has no
actual ranked worker/collector launch path, key generation, model execution,
encrypted batch result or timing claim. Retained-key request-state changes are
deferred; the intended first implementation follows the official fresh-key path.

All217 source files of the active stage4-v2 predecessor were copied exactly.
`runtime/` and `joined/` contain unchanged arithmetic, full12+pooler/head owner,
file handlers, transport and lifecycle code. Dormant predecessor top-level
collectors live under `predecessor_stage4/` and are never selected by these
tests. `source_origin.json` binds every copy; old source evidence remains intact.
The additional public reports/archives include no input/reference/key/CT bodies.

`ranked_case_gate.authenticate` authenticates the exact nine-case tokenizer
producer and completed native-reference publication before any private access.
It returns frozen CaseSet/RankedCase/Workspace/ReferenceFile descriptors, not
permission to execute. Official reference availability requires complete
publication/retention/error-absence/source/assets/cleanup/terminal gates and is
independent of approximate diagnostic success. Selection is exact integer
size/seed, preserving all100/200/408 ordered rows and the original input/order
hashes. Prepared input paths are expected fixture identities, never permission
to skip timed fresh official preprocessing.

`ranked_private_reference.load` is a future client-only API. It holds the
authenticated0700 root, checks all11 regular0600 descriptors and unchanged
metadata, authenticates the manifest and selected bounded file, and validates
all-nine manifest bindings plus selected row/target order, positions and official
accuracy. It returns immutable private selected rows; no raw values are logged.
Development tests use newly owned synthetic fixtures only. Actual original54
inputs,11 references, keys and the live size0 ledger remain untouched.

`ranked_readback.requests/responses` process all8N input tiles and N responses in
order, matching canonical aggregate digests and actual metadata. Their callers
must first authenticate completed producer evidence; payload reading is not
performed by public gates. `client_results` validates every ordered finite
private output, original target, and the complete decryption receipt. Public
results contain hashes and aggregate metrics only. `ranked_stage_gate` specifies
strict externally pinned future stage3/4/5 worker/report/source/terminal proofs;
it deliberately cannot accept old size0 reports. Real worker integration remains
required. Source inventories must come from an independent review, not from the
producer report being authenticated.

Official ranked labels use class1 on equal logits, at least75% accuracy and at
most2percentage-point loss:4*HE_correct>=3*N and
100*(official_correct-HE_correct)<=2*N. Exact label/output order and postprocessed
prediction consistency are mandatory. Native prediction agreement is diagnostic;
per-logit and approximate-reference screens do not become ranked acceptance
requirements. A successful decryption receipt alone cannot grant final ranked
acceptance or retirement. Outer orchestration must wait for postprocessing,
strict checks and evidence preservation before authorizing owned cleanup.

Synthetic handler tests execute the unchanged five file-handler loops at all
three ranked counts with actual packer/manifest/receipt code, but explicit tiny
key, encryption, full-model graph and ciphertext-transport doubles. They verify
N graph calls,8N encryptions,N decryptions, exact order/positions and shared-engine
lifecycle; they do not execute the real graph or validate HE batching. A synthetic
filesystem budget is explicit because placeholder transport uses tiny files.
The real capacity guard initially rejected these tests on the current root
filesystem; that fixture failure is preserved. Last-record corruption, late
cancellation, full408 nested replacement and partial-retirement retry are covered.

`ranked_private_io` is a new local helper. The copied older BorrowedFixtures
metadata checks remain unchanged. It distinguishes a real read-body primary from
cleanup-only file-close errors, attempts every directory release, preserves a
body primary, lets cleanup-only cancellation take precedence over ordinary
cleanup errors, and quarantines uncertain descriptors without retrying them.
Independent negative evidence and repaired tests are preserved separately.

outer collectors, complete private-result integration, installed entrypoint
