# Isolated scaled CRT conversion successor

This future-runtime candidate changes only one helper and two conversion calls in an exact copy of the original 199-source optimized sweep. It is not installed or promoted. The original BERT toy5 failure remains unchanged; its exact throw site is inferred from source and the error message, not established by a traceback or retained ciphertext.

The normal path remains `float(value) * scale_inv` in the original order. Only an overflowing integer conversion uses division by the exact integer ratio of the binary64 scale. A mathematically representable scaled value can therefore survive a nonrepresentable unscaled integer. A nonrepresentable scaled result still raises. No magnitude restriction, clipping, coefficient, scale, modulus, tolerance, or original 1/32 approximation gate changes.

The tests import the actual isolated module after CPU environment selection. Genuine uint64 residues are independently constructed by integer modulo under the public recorded 40-prime output modulus. Production CRT, conjugate/noise code, and FFT run without substitutions. Constant real coefficient zero gives independently derived Fraction-scaled constant slots; asymmetric real and imaginary coefficients retain the original rejection. Both small rings and the actual 131072 degree/65536 slots are covered. Representable old/new decoding uses the original decode AST with the same unchanged real dependencies and compares binary64 bits. This AST reference does not replace CRT or FFT.

The test process forbids libtpu/model-framework imports, accelerator-device opens, and libtpu dlopen; it checks CPU devices and an unloaded TPU plugin. Optional libtpu discovery by JAX is denied and recorded. Context construction, encryption, decryption, and key-generation functions are additionally guarded after import. Importing public backend constants initializes the JAX CPU backend. NumPy CPU arithmetic executes the actual decoder. This is clear arithmetic/unit evidence, not ciphertext decryption, HE precision repair, model execution, or recovery of the encrypted toy5 result. Python guards are test boundaries, not an OS sandbox.
