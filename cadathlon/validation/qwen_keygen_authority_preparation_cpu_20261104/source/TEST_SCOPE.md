# Focused pure keygen authority tests — source held, not run

This successor preserves every byte of the reviewed28 source snapshot. It adds five Python test/fixture files, one exact public aggregate metadata copy, the parent inventory, and test-selection/provenance documents. No inherited test suite is selected. Static AST parsing finds48 intended cases:17 launch/model/source cases,25 generated-readiness cases and6 retained-state/actual-entry cases. There has been no candidate import, pytest collection or test execution.

The positive fixture builds a synthetic public ModelAdmission chain and a335-entry public key manifest containing only shape, dtype, declared byte extent and invented digest metadata. It never allocates those arrays or reads a key/model file. Model report inode/process/grant/source values and all new key report/outer/root claims are synthetic. The aggregate/catalog bytes are existing fixed public metadata; they provide shapes and declared hashes only. The completed metadata-only acquisition is neither imported nor used as a model proof.

Mutation hooks deliberately rebuild surrounding hashes after changing individual documents. This makes invalid report/outer/root/model semantics reach the actual pure gates instead of only failing an external hash comparison. The fixtures are trusted synthetic callers for these tests; their self-consistent pins are not evidence of an independent actual review. No generated test document is a valid operational grant or readiness receipt, and none is published as one.

The production boundary's parent acquisition, memory authorization, real role selection and actual keygen process remain absent. Tests only check the pure binding required from those later mechanisms. They do not turn any report boolean into an observed filesystem, backend or process fact.
