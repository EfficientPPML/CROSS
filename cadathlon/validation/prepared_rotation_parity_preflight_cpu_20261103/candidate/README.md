# Prepared rotation parity preparation

This isolated successor copies the frozen stage4-v2 217-source closure. The only runtime overlays are the exact reviewed `key_contexts.py`, `loader_prepared_rotation.py`, and `prepared_rotation.py` from the 116-check loader successor. `parity_origin.json` records every original byte and the overlay hashes; `dependencies.json` records the changed loader dependency. Existing stage4 worker/collector/tests remain dormant provenance.

The proposed actual run reuses authenticated stage1 public keys and stage3 encrypted tile0. It authenticates the completed stage1, stage2 and stage3 public reports, exact source archives, retained public directory identities and all eight ordered upload descriptors before loading any ciphertext. The actual worker then verifies all eight public ciphertext payloads before and after work. It never opens client-private data, native inputs, model tensor payloads or secret keys; it performs no key generation, client codec, refresh or model evaluation. These are regression boundaries, not an OS sandbox.

One borrowed keyless context serves two serial `CompiledArithmetic` owners. The ordinary owner and one prepared owner each rotate the same unchanged input by `[1,1,64,64,1,64]`, first at level49 and then at level25: 24 genuine rotation calls and 12 exact comparisons. Level25 is created by the actual level-reduction operator; its entire payload must equal the ordered Q52 prefix of the original Q100 payload, with unchanged actual scale and explicit NSD1. Every uint32 output word, modulus, layout, precision, scale and NSD must match the ordinary implementation. Input fingerprints are retained. There is no decryption or plaintext accuracy gate.

The prepared owner has at most two entries and a 2GiB logical device-array limit. The exact two-entry counts are 1,913,651,200 bytes at level49 and 554,696,704 bytes at level25, including coefficient maps. Four hits/two publications per level are required. These exclude the authenticated 130-key host mappings, their referenced backing/page cache, compiler controls, allocator reservations and conversion temporaries. They are not peak-memory or speed claims. Baseline executes first in each pair; elapsed times are diagnostics with uncontrolled warm-cache effects.

The loader's explicit no-write contract applies to the authenticated public key directory for the whole borrowed lifetime. Concurrent readers (including root's stage4 process) are allowed; readonly mmap and inode/stat checks alone do not establish adversarial immutability. Both compiled owners finish and retire their original controls before the loader may retire mappings. Any uncertain body/readiness/retirement failure propagates into the loader's existing process-lifetime quarantine. Original owner cleanup methods are captured at construction. External directories are never removed. The outer collector borrows only `upload`; legitimate creation of sibling `download` or `server_report` is ignored and those files are never touched.

Preparation tests use tiny synthetic arrays and mocked processes. The separate installed probe imports the actual source closure, denies/restores all 28 entrypoints and verifies loaded source paths without constructing a context or reading payloads. Public preflight uses actual security/P-coverage functions and may initialize the CPU backend; it creates no CKKS context or keys. Every actual launch requires a new explicit root grant after review; no actual run has been launched by this preparation.

Planned command uses `parity_collect.py --execute`, `JAX_PLATFORMS=cpu`, four bounded BLAS/OMP threads and affinity140–143. The worker runs from a byte-verified isolated execution-source copy and receives only public prerequisite paths. The corrected generic process owner provides no healthy timeout, 120-second graceful cancellation, process-group cleanup and reaping. Terminal publication is outside the cleanup scope and failure is republished as failed. The inherited generic process `passed` field is not an encrypted metric here; authoritative acceptance additionally checks the numeric exit, reaping, the hash-bound worker report, exact sources, all twelve comparisons and cache/level records.
