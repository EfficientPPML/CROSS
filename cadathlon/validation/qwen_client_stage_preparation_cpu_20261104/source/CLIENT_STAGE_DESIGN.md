# Client input/output recording glue

This successor preserves every source in the admitted366 parent exactly. Only
`client_stage.py` and explicit client provenance/design files are added. Actual
client factories deny before argument access. There is no real backend factory,
key generation, model/token lookup, active role grant, or new numerical rule.
No tests have run at the initial held source-review checkpoint.

`publish_input_for_recording` takes full client `FilesAdmission`, existing-key
paths, trusted synthetic original embeddings/positions, exact recording key
dependencies and `RecordingInputFactories(publisher, secure, shield)`. Complete
public/key/source identity checks precede placement, callbacks, key reads and
owned publication. Existing placement produces immutable65536-slot row tiles.
The original context `encrypt_slots` callback is captured and invoked once per
tile with exact fresh scale. The inherited metadata gate requires full freshL49
Q100/batch1/precision32/NSD1. A real owned Publisher writes one/two tiles and the
canonical complete upload. Its original write/finish/close callbacks are captured
immediately and checked before and after callbacks and cleanup.

The result `PublishedRequest` contains canonical request/upload bytes and input
digest. It is not a producer/outer terminal receipt. Return occurs only after
publisher close, retained ciphertext barriers and nested key-loader exit.

`consume_output_for_recording` first validates full client admission and an exact
original request/digest. Its trusted `response_files` factory must return the
actual `ResponseFiles` owner for that same public/request identity. Construction
and a complete held readback occur before the private-loader callback. Existing
`ResponseFiles` authenticates all38 containers and independently pinned producer
proofs. This wrapper does not invent a producer receipt or follow private paths
from a merely structural document.

The composite `_consumer_scope` runs inside `_load_for_recording`. It yields a
consumer handle retaining the original context/key handle, exact default codec
method, public manifest and run-local original/partial ciphertext arrays. The
output materializer is an explicitly trusted synthetic callback, passed a fresh
copy of each immutable binding; its result is checked against the preserved
binding. The context's captured `decrypt_slots` is called with actual scale,
`slots_to_decode=65536`, and `validate_approximation=True`. This is the selected
defaultbc978 facade signature; the optional decoder is not selected.

Unchanged `ResponseFiles.run_client` checks exact all-slot finite float64 and
copies each entire decoded65536 vector into immutable bytes before the next
decoder call. The reviewed layout joins37×4096+384 row-zero entries. The wrapper
does not average aliases, clip values, truncate padding checks, select coefficients
or introduce a tolerance.

The composite scope retires original ciphertext consumers before its nested key
loader can dispose the context/backing maps. Barriers use retained original
arrays; callback/handle/manifest/factory checks also run around retirement.
An entered failure or uncertain readiness retains the original consumer graph
and propagates into the key loader, which quarantines context/key backing. Both
layers use exact Toy4v4 cleanup-origin rules and the reviewed new finalizer.
Repeated roles after a client-stage quarantine are rejected. Client/server
scopes stay serial and nonoverlapping; no default125 generation helper is added.

Future focused tests will use trusted synthetic embeddings, real owned synthetic
Publisher/ResponseFiles files, complete synthetic key metadata with recording
maps/security/backend dependencies, and recorded default-codec signatures. They
must cover1/2 fresh inputs, all38-before-private ordering, decoder scratch reuse,
body/cancellation/late-callback failures, original ownership and cleanup order.
They will run only after this held source/delta is reviewed. They will not prove
real full-size key bodies, actual contexts/codecs/device barriers, signals, model
or HE execution, process startup/grants, or official numerical acceptance.
