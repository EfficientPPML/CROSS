# Qwen D128/Q16/K8 head and causal-score owner

This isolated experimental component implements real ciphertext-operation loops for the pinned full-width Qwen geometry and unchanged candidate3/config bytes. It borrows an initialized keyless `CompiledArithmetic` and never owns/closes it. There is no codec, key generation, refresh, RMSNorm, softmax, PV, native fallback or full-model claim. No live runtime or frozen proof file is changed.

`QwenHeadRouting(arithmetic, manifest_bytes, config_bytes, positions=..., progress=None)` binds the context, actual ordered Q/P, arithmetic strategy/scale, full65536-slot layout, public original positions, callback and supplied reusable rotation key/map identities. It rejects bound-aware/implicitly refreshed arithmetic. Inputs require exact typed batch1/two-component/N131072/CD2/NSD1 metadata, secure execution validation, positive actual scale and two reserved output levels. Callback continuation checks original inputs and the live accumulated score; result annotations do not inherit unproved `_public_*` contracts.

Each F4096 row is a distinct token. `expand_kv(value,tile=...)` expands8×128 features to16×128 by adjacent head repetition, with zero inactive rows/features; one weighted stage and8 rotations. `rope(value,tile=...,heads=8|16)` applies the frozen public NumPy frequency construction with original position IDs and half-split128 pairing; one weighted stage and2 rotations. The pinned config permits positions0..40959. No adjacent-pair RoPE or hidden/heads=64 shortcut is used.

`scores(query, expanded_rope_key_tiles, query_tile=...)` accepts the actual post-normalization/RoPE Q and expanded K ciphertexts. For each key it performs a public row broadcast, one CT product, seven head128 sum rotations, then routes only aligned head anchors and multiplies by1/sqrt128. A final key offset places score(h,k) at feature32h+k. Causal/future/inactive slots are zero under the public original-position ordering. This costs three levels below the minimum input as a conservative bound; with Q at25 and expanded K at24, output is21. Head-anchor compaction uses15 shared offsets instead of a separate16-offset inventory per key. S32 requires77 component rotation keys; it is not the complete model key inventory. `public_plan.json` records actual counts and binary64 scale replay from the fixed p60/d8 ordered primes. Actual returned scale is checked; no scale is relabeled.

`test_head_routing.py` executes these exact owner loops with NumPy primitive doubles that model the production scale ordering and ciphertext metadata. It compares all65536 slots against independent dense QK and scalar half-split oracles for S1/8/16/19/32, distinct rows/heads, partial tiles, hostile padding, noncontiguous positions and the config maximum. It also exercises callback/layout/key/type/cancellation guards. The doubles replace the crypto type/security seam; these tests do not execute actual security/keygen/HE and do not prove CKKS error, timing or memory. The actual owner calls the existing `require_secure_execution` before any primitive. A future genuine run requires its complete crypto dependency closure and measured keys/profile first.

The first development run passed33 tests and failed2 RoPE oracle comparisons (3skips for nonexistent second tiles). Python scalar power produced different public frequencies from the frozen NumPy expression, with worst4.663e−15. The original source/log are preserved. The corrected independent oracle uses the exact frozen frequency construction while retaining independent scalar half-split arithmetic and the same3e−15 threshold; score threshold5e−14 is unchanged. Later tests include all valid tile cases without skips. Development snapshots are not encrypted results.
