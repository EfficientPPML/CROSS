# Complete initial proof and granted initial selection

This successor preserves all 18 files of the measured selector preparation byte-for-byte. New code implements a real initial-selection path, but its source readiness is false by default, no root grant has been issued, and preparation uses only synthetic reports, reconstructed statistics and grants. No actual initial observer report, journal, token, model, validation body or range has been read. Synthetic tests may exercise the production branch and its actual-selection output schema; their reports are not real selection evidence.

`entry.py` uses the reviewed observer's isolated stdlib bootstrap before any local helper import. It requires `-I -B`, an externally pinned exact source manifest, an exact source tree with no extra files/symlinks, and no local preloaded alias through file or spec origins. A frozen importer serves authenticated local bytes and rejects model/HE backends. Actual dispatch additionally requires `--execute`, `--grant` and an externally pinned `--grant-sha256`. The grant binds this source inventory, successful preflight and independent review hashes, exact observer public proof paths/hashes/sizes, output path, fixed candidate ordinal 1, protocol, protected candidate3 bytes and gate bounds. No retained or default grant can activate it.

`initial_proof.authenticate_initial(parent_bytes, worker_bytes, archive_bytes, root_bytes, *, pins, root_outer_bytes)` performs no IO. It authenticates the exact reviewed 61-member producer inventory against SHA8131c5ac..., every source archive member, both terminal reports, the original model/backend/calibration/protocol bindings, native model loading, and exactly 3,232 started/completed native calls. It requires ordered 3,200-context aggregate accounting, all 32 invariance checks and 64 complete baseline-generator contexts, without including baseline ranges. Caller-supplied pins are not an authorization capability; actual entry obtains them only from the externally pinned root grant.

Root reconstruction uses exact reviewed script SHA3690b5710a8f019f529062303289d415fad99d85bb579ff426e66ec9633ff2e3. Its review schema is `qwen-initial3200-root-review-contract-v2`, the agreed v1 fields plus native model/call facts, script hash, immutable snapshot descriptor, calibration hash, private inventory hash, private_files=9666 and private_journals_immutable_at_review. A separate externally pinned `qwen-initial3200-root-reconstruction-terminal-v1` receipt must contain exactly exit_code=0, reaped=true, process_group_absent=true, review_sha256 and script_sha256. This receipt is created only after root's authoritative script terminal observation; a PASS-looking review written before failed final close is insufficient.

`authenticate_snapshot(snapshot_bytes, binding)` is also IO-free. The snapshot schema is `qwen-initial3200-reconstructed-snapshot-v1`, with parent/worker/archive/source/calibration pins, input_ranges, ledger_sha256 and inventory. Exact 9,666 names are required: all 3,200 started/native/exact phase files, 64 free baseline files and initial-ledger.json/input-ranges.json. Each descriptor binds SHA256, size and unique device/inode. Its inventory hash uses `json.dumps(sort_keys=True, indent=2, allow_nan=False)+'\n'`, exactly matching root's script. Root privately verifies all original tokens, prefixes, choices, per-context site counts, hashes and aggregation. This consumer verifies the immutable snapshot digest and producer bindings, recomputes strict aggregate counts/per-K union, checks the private ledger/range descriptors and compares reconstructed ranges to the worker report. It does not reopen original journals or calibration.

Proof authenticity accepts every finite strictly positive normalization variance. The unchanged selector policy separately rejects minima below its pinned binary64 epsilon; a legitimate float32 epsilon-only observation can thus be authentic but unsupported for this frozen policy. No floor exception, coefficient fit, old-count reuse or protected rule change is introduced.

The process authenticates all public evidence before opening the one private snapshot. It uses a held 0700 parent and 0600 snapshot inode, bounded FD reads, immutable bytes, and a second hash/identity read after selection. Its output must be fresh and disjoint from source, proof, original private/calibration/model trees and snapshot parent. All those inputs remain read-only. A scoped audit allows only source, public proofs, the one snapshot, interpreter libraries and owned output; it denies other file IO, process/network and backend imports. This is an in-process integrity boundary, not an OS sandbox.

The selection boundary hashes the exact norm_multipliers bytes (761a07e2...) and protected candidate3 bytes (7f6478a6...). It delegates all 113 uniform interval/degree/Newton/certificate/grid decisions to the unchanged measured mathematical core. Unsupported or overflowed selection retains failed attempts and preceding assessments. All 28 SiLU and softmax rules, exp8 and reciprocal maps/counts remain unchanged. Only initial ordinal 1 is supported; candidates 2/3 need the separate revision successor.

Successful publication names are candidate_manifest.json, assessments.json and protected_checks.json. The candidate schema is `qwen-expanded-initial-selection-v1`, with candidate_index=candidate_ordinal=1, synthetic_only=false, actual_coefficient_selection=true, protected parent/protocol/source/grant/initial proof/snapshot pins and all support flags. There is no fictitious selector worker. A failed supported-domain check retains completed outputs but passed=false; consumers must require passed=true, all support flags and independent terminal evidence.

Final publication occurs after body cleanup and signal restoration attempts. A final report write/close error may still leave a report, so every consumer must require an independently authenticated process exit0/reap/group-absence receipt and exact report hash. No self-published success replaces that terminal evidence. Any recorded audit denial vetoes the report and zero exit even if its exception was swallowed internally. Original protected-body/cleanup-only cancellation precedence and single-fire signal ordering are reused; cleanup-shield setup is explicitly classified as cleanup, and an entry failure falls back to all cleanup actions; main-thread masks are not process-wide atomicity claims.
