# Prospective client-only decoder comparison

This is a bounded source/public-metadata review and disabled design. It does not alter the queued Toy4 diagnostic260, original199, isolated decoder207, installed backend, any grants, or the accelerator queue. No key/ciphertext/model/validation body was opened and no runtime module was imported or executed for this review.

## Keep the original localization

The unchanged Toy4 validator calls `handle.ctx.decrypt_slots(value)` independently for all96 authenticated checkpoints, retains each decoder exception, and preserves the original 1/32 conjugate/noise gate. Its full-slot absolute1e-6 diagnostic and final toy absolute0.02+relative0.01/exact-prediction gates remain authoritative for that run. The new conversion is not a replacement for this first localization. A candidate returning a finite large value would still require those unchanged numerical gates; merely reaching FFT is not success or evidence of encrypted precision.

The original Toy4 failure was an approximation-error rejection with nonfinite estimated noise; the fallback only addresses integer-conversion overflow and is not a proposed fix for that recorded rejection. A Toy4 comparison cannot establish the behavior of the distinct three-layer Toy5 ciphertext.

The BERT test5 public record reports OverflowError after eight refresh completions and publishes final ciphertext metadata, but no traceback or ciphertext/coefficient body. Its process record reports the public key store removed. The precise throw site remains an inference. This design cannot recover or retrospectively decode that completed run from current public evidence.

## Retention must be established, not presumed

Exact260 `collect.py` sets `workspace_retained=True` after successful configuration, and both role/outer cleanup explicitly retain keys, ciphertexts and public weights while retiring owned OS processes. `key_contexts` closes or quarantines mappings/context; it does not remove stored keys. Failed setup key generation may roll back its newly owned key directories. Therefore a *future successful setup and completed server* can leave material available under the existing source contract. No actual Toy4 workspace is presently asserted to exist.

A comparison grant must additionally bind the owner's continued retention of the particular workspace dev/inode, complete public/private key inventory, request/input digest, and all96 checkpoint manifests. The consumer reauthenticates all artifacts immediately before use. If an external owner has retired material, a required identity/body is missing, or setup/server is incomplete, comparison is unavailable. Do not retry the graph, regenerate keys, reconstruct a workspace, or change retention inside frozen260. Any requested producer capture/retention change would require a separate reviewed producer successor and new grant; it is not needed merely to express this conditional design.

## Minimal separate consumer

The successor is a client-only comparison role, not another server run. It first authenticates external source/grant bytes, completed setup/server receipts, independent root server review, authoritative producer exit/reap/group absence and owner retention. Then it authenticates all96 opaque files and independently replays the same five actual refresh scales/all96 metadata rows before any private key read. Original fresh isolated-source bootstrap and held output ownership requirements remain necessary.

Existing260 `terminal_gate(expected_sources=...)` requires the prior producer map to equal its expected map. A new consumer must not supply its own map or silently bypass that check: provide a separate, hard-pinned original260 producer map to the unchanged producer gate, independently bind the new consumer map, and bind the old decoder199 and new decoder207 candidate file/map/archive identities. The external review/grant needs explicit producer and consumer fields. The existing root-review helper's consumer-source field alone is not a dual-source admission contract. These are future consumer-only changes; none are applied here.

The original queued validation remains unchanged. After its attempt is externally closed, a separate comparison grant may admit the completed successful *server* evidence even if original client decoding failed. It does not treat the failed validator as successful prerequisite evidence. The earlier validator report and outcome are immutable inputs to the comparison report. Server work must already be terminal; no private result returns to server arithmetic, coefficient selection, scale planning, or future fixture selection.

## Same owned input, two fixed decode branches

For each predetermined index0..95, reauthenticate the exact same ciphertext artifact and replayed scale. Resolve the scale with the original `_resolve_codec_scale`, retain the original ciphertext wrapper and payload, and use the original `_fast_decrypt_to_rns_coeffs` path (including canonical context validation and single-batch host transfer) once. This gives one owned CPU uint64 coefficient matrix. Both branches receive the same read-only matrix, Q prefix, original context view, scale and all65536-slot request. No recentering, rescaling, clipping, alternate slots, skip flag, or coefficient replacement is allowed.

Run the original `_fast_decode` first, then the fixed helper+two-call decoder. Their globals must be separate so importing the new `ckks_ctx` cannot replace original flat/package aliases. One prospective binding method is to authenticate both full module bytes and their reviewed whole-AST delta, compile each exact decode definition (plus the new helper) in separate namespaces sharing the original unchanged CRT/FFT/noise definitions. This is a source-bound diagnostic binding, not an installed module swap. Prove binding equivalence with synthetic tests before any actual consumer grant.

Both decode calls run the original 1/32 gate. Keep original and candidate outputs/results separate. Known synchronous OverflowError/ApproximationErrorTooHigh can be recorded independently and the other branch attempted on the same already-ready CPU matrix. Cancellation, unknown readiness/transfer failure, source/identity drift, or structural failure aborts the dependent comparison, records incomplete status, and triggers the existing client failure quarantine. Do not reinterpret an infrastructure abort as a scientific failure or clean terminal result. Retain source/host arrays and wrappers explicitly through callbacks and failure finalization; no reliance on mutable wrapper references or traceback lifetime. Compare read-only coefficient identity/content privately before/after both calls, then retire only when readiness is proved. An unresolved owner remains quarantined until dedicated-process exit.

Public report fields per branch: index, fixed checkpoint label, exact source binding, actual metadata, attempted/completed, decoder exception class, finite flag, original numerical gate results, and optional finite old/new output difference. No decrypted arrays, coefficient values, secret descriptors or coefficient hashes in the public archive. A private witness may bind coefficient bytes for independent readback. If one branch fails, there is no fabricated pairwise error. Any old failure remains an old failure even if the candidate branch passes. Candidate comparison is diagnostic and cannot replace the original aggregate or authorize reuse, retuning, or model claims.

## Necessary missing localization evidence

A source-bound optional trace can record only entry/completion of original CRT, conjugation, noise check and FFT calls in each branch's private namespace. Wrappers must delegate exactly once, preserve argument/result identity and primary exceptions, and never change globals of the installed original module. CRT-completed with no conjugation entry localizes a conversion-stage failure more precisely than the current message; it still must not infer encrypted correctness. This is proposed instrumentation only. The existing207 clear arithmetic proof does not measure an actual ciphertext.

Serial comparison retains one ciphertext and one RNS matrix at a time. At maximum100 limbs and degree131072, the host uint64 ciphertext representation is 209,715,200 bytes; decrypted uint64 RNS is104,857,600 bytes; each decoded65536 float64 vector is524,288 bytes. Both CRT passes additionally allocate Python-integer lists and FFT temporaries; these logical sizes are not a peak-memory bound. No additional key generation, rotations, ciphertext checkpoints or server storage is required *if* the exact workspace remains retained and admitted. Do not archive coefficient/slot bodies or clone the key store. Any actual client platform/grant must be separately reviewed; this design does not switch the original TPU role policy to CPU.

Source-bound preparation and peer review are prerequisites to any separately granted readback. No actual mode exists in this capsule.
