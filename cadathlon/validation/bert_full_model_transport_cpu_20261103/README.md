# Full-model tile transport candidate

This isolated adapter validates and serializes eight fresh ciphertext tiles for one opaque sample and one two-logit response. It implements no key loader, five-stage handler, encryption or full-model inference. The parent authenticates the public key/model manifests and retains private target-ID mappings.

1. Build `public` with exactly `context_id`, `model_id`, `checkpoint_sha256`, `config_sha256`, `candidate_sha256`, `profile_sha256`, and `parameters`. Context/model IDs must come from independently authenticated manifests. `transport_contract.parameters()` returns the pinned N131072/CD2/depth49/p60/d8 Q100/P14 profile. The module pins the other four hashes; self-authenticated hashes are not origin authentication.
2. Call `transport_contract.make_contract(public, opaque_request_id, prepared_input.public_metadata())`. This validates all original positions, original/compacted masks, eight tile valid-row counts, original-position-before-compaction declaration, and output logit slots0/1. Token IDs and private target indices are not accepted in this schema.
3. For each ordered tile0..7, `save_ciphertext(ct, fresh_directory, contract=..., role='request', tile_index=i)` publishes one three-file directory. `validate_ciphertext` checks bytes without a backend; `load_ciphertext` constructs a Polynomial only after those checks. The parent owns aggregate request publication and group/process cleanup.
4. Compute `request_digest(list_of_eight_validated_manifests, contract)`. Save the original digest privately on the client. The digest binds ordered tile artifact hashes, request nonce, public positions/masks and public identities. It does not establish authenticity of an arbitrary caller-supplied manifest.
5. The response uses `role='response', tile_index=0, expected_scale=actual_public_operation_plan_scale, input_digest=original_request_digest`. Level2/Q6/NSD1 and exact binary64 scale are required; no metadata relabeling or tolerance is used. Client reads slots0/1 as logits. This artifact validator cannot prove ciphertext slot semantics or numerical accuracy.

The writer reuses the historical P1 `bundle_io.save_bundle` only in a fresh owned tile directory. Readers do not call its permissive loader. Reads pin the directory fd and use O_NOFOLLOW/O_NONBLOCK; exact file/ZIP/NPY inventory, uncompressed sizes, NPY header dtype/shape/order and byte counts precede array allocation. Actual residues are checked before Polynomial construction. A held fd/dev+ino guard retains moved/replaced paths and preserves primary cancellation when cleanup also fails. This is a concurrency guard, not an OS sandbox against arbitrary same-user mutation.

Development-v1's unavailable private NumPy header API failure is retained with exact sources; v2 uses public header readers and passes71 tests. Tests use fake Polynomial wrappers and zero payloads, including the full104857600-byte request and6291456-byte response shapes. No genuine ciphertext or HE claim is made. No raw payloads, keys, model arrays or client inputs are archived.
