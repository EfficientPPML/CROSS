# Full-BERT authenticated key context adapters

`load_client(public_keys, client_private, *, profile_bytes, plan_bytes)` and `load_server(public_keys, *, profile_bytes, plan_bytes)` are separate from actual key generation. This checkpoint exercises public metadata/security predicates and tiny mocked key/context lifecycle tests. It creates no real keys, CKKS context, ciphertext or encrypted result.

The client authenticates the complete public inventory, retains only read-only PKE/secret maps, and builds a codec-only context. The two client-owned optional files `requests.json` and `completed.json` are allowed but are not trusted by this loader. The server receives no private path, maps public rotation arrays without copying the complete116 GiB store, converts only two relinearization arrays for initialization, and contains no secret or public PKE key. Both key-generation module spellings and all seven client codecs are blocked before server construction/setup; public encode methods remain available for model constants. The handler owns arithmetic/compiled bindings and must finish/close them before loader exit.

Authentication uses bounded NPY headers, exact shapes/dtypes/hashes/canonical residues and the same retained file descriptor for hashing and mapping. Directories are pinned and checked against visible paths. Keys and manifests are checked again after the stage. Ordinary cleanup waits for setup and still-reachable lazy rotation transfers, invalidates context/cache ownership, clears process dispatch/Polynomial state, closes maps and directories, and restores all guards. Cleanup attempts every operation and preserves primary exceptions; repeated INT/TERM/HUP signals are deferred through cleanup.

If any transfer readiness remains unknown, or any entered server stage raises after lazy controls may already have been discarded, all public host backing and reachable transfer owners are quarantined until the dedicated process exits. Further loader use is rejected. This deliberately reports **incomplete cleanup** and never claims reclamation. It does not close a potentially active host mapping. Normal successful stages still close all resources.
