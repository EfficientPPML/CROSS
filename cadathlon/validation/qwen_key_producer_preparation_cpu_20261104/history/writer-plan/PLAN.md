# Minimal unbuffered NPY sink proposal

Preserve held64 (`d072e281…`) unchanged. Security receipt `fc9f6144…` identifies an unresolved uncertain buffered-stream-close/raw-FD retirement branch, not a reproduced ordinary flush-error corruption. BufferedWriter normally attempts raw.close after a flush error; an ordinary flush OSError or an earlier successful explicit flush does not establish pending bytes. No runtime negative is claimed here. This plan and its patch are source-only, unapplied, and untested.

Replace only the NPY **writer** handoff in `qwen_key_store.write_array`. Add a plain `_NpySink` helper in that module. It retains the original `_StoredFile` owner and its initial numeric fd but has no buffer, `fileno`, `flush`, `close`, destructor or IOBase inheritance. Its sole data operation is synchronous `write(data)`: borrow a byte memoryview, reject a cumulative extent beyond `spec.raw_bytes+4096` before issuing any writes for that call, then loop over at-most-CHUNK (1MiB) views with os.write. Every reported progress must be an exact positive int no larger than the supplied slice. Return the original input byte count only when the entire call is written. A syscall exception propagates immediately; do not retry or replay bytes whose write status is uncertain.

Before every syscall the sink checks that the original owner still holds its captured fd. The owner already detaches that field before raw close, so even a retained sink cannot write to a reused numeric descriptor after retirement. `write_array` invalidates the sink on every exit from np.save using the existing `_CloseState.cleanup` policy, protecting a genuine body exception if cancellation occurs during invalidation. Invalidation only clears borrowed references; it performs no OS I/O or close. The original `_StoredFile` remains the sole descriptor-close owner. No object destruction can initiate a write or close. The shared `_stream` helper remains byte-identical and is still used for the unchanged **read-only** bounded-header path.

`proposed.patch.txt` gives the exact unapplied delta against store1ebd2db1. It adds `_NpySink` and replaces the `_stream(...,'wb') / np.save / flush` block with `np.save(sink,...)` plus guaranteed invalidation. The existing `_array`, extent checks, original file/directory identities, fsync, SHA/residue/header readback, manifest order, shared cleanup selector, root/private permissions and quarantine remain unchanged. Producerf85277 and all57 copied dependencies remain exact. A later successor would change only this store source and truthful design/provenance metadata, adding narrow tests after approval. No core randomness, Q/P/profile, key schemas, literal166 inventory,335 descriptors or actual role is changed.

Installed-source evidence is pinned in `source_refs.json`. The intended eventual test interpreter is `/tmp/cross-pretrained-validation-env/bin/python -I -B`; NumPy's actual source is under `/home/jianming_gatech/miniconda3/envs/jaxite/lib/python3.13/site-packages/numpy`, not the venv's site-packages directory. `_npyio_impl.save` selects nullcontext for an object with `.write`, so it does not open or close the sink. `_format_impl.isfileobj` accepts only FileIO/BufferedReader/BufferedWriter, so this plain object avoids the tofile path. `write_array` writes the same header generator output and, for the validated ordinary uint32 dtype, emits ordered nditer chunks as bytes. It requests a16MiB element buffer; the bytes for one chunk and any iterator buffer are transient, and the sink itself adds only memoryviews/counters. This is a source-derived bounded-chunk argument, not a measured peak-RAM guarantee. No full key or335-array bytes concatenation is added. Existing generation/storage arrays and conversion copies remain outside this new sink's incremental memory claim.

NPY wire behavior is intended to stay exact: np.save still chooses the version/header and controls C/F traversal; the sink changes only delivery of the emitted bytes. The unchanged reader continues to reject non-C order, wrong dtype/shape/extent/residue and oversized headers. Byte-for-byte agreement against np.save to a small BytesIO/control file must be demonstrated by the later tests before claiming compatibility. The new code must not choose its own NPY header, cast/clamp values, change shape/order, or normalize bytes.

Coupling the existing BufferedWriter and raw-FD owner in quarantine is the alternative, but it would require proving that every stream is conclusively closed before closing its fd, retaining both on uncertain closure, and extending finalization/descriptor-budget behavior across the shared helper. That is a larger lifecycle change and still leaves a buffered writer reachable in failure state. The plain sink removes the pending user-space write mechanism and any automatic close authority, while preserving the already-reviewed sole raw-descriptor owner. Kernel buffering remains governed by the existing fsync/readback checks; this is not an atomicity or durability guarantee beyond those checks.

The proposed narrow tests, only after approval, are:

1. **Exact owned NPY control:** write small genuine C-order uint32 residue arrays through the new KeyStore; compare exact NPY bytes with a pinned np.save BytesIO control, then use the unchanged512-byte header and residue/hash readback. Check the two production key shape ranks using small dimensions, without allocating real key-sized arrays. Record the loaded NumPy source origins.
2. **Write-all and cap:** a recording os.write returns a sequence of positive short counts; verify identical byte order, CHUNK maximum and returned total. Parameterize zero, negative, boolean and oversized counts as failures. A call that would exceed the cumulative raw_bytes+4096 ceiling must issue zero further writes. Empty writes return zero without a syscall.
3. **Raised write/body/cancellation:** after a known recorded prefix, raise OSError or KeyboardInterrupt from os.write; verify exact exception identity, no later/replayed write, invalidation, and original owner cleanup. A known np.save body ValueError combined with a cleanup cancellation must retain that genuine primary under the shared policy. These are controlled synthetic failures, not claimed OS/NumPy failures.
4. **Retired fd reuse:** invalidate/detach the original owner, then reuse the same numeric fd for a second newly owned small file in a controlled test (dup2, if needed, is a test-only reuse stimulus, never production descriptor handoff). A retained sink must reject before os.write and leave the second file unchanged. Also check no-close/no-destructor/no-fileno/flush interface and normal sole-owner retirement.
5. **Integrated failure remains incomplete:** an injected sink/write failure during one owned small key file must leave no successful manifest/return and retain failed owned evidence; all original descriptor closes are attempted once, with existing body/cleanup precedence. No inherited43/366 suite, actual keygen or backend/context import is needed.

There is no need to manufacture a broad old-runtime failure matrix. If an old held64 comparison is later required, it must be one explicitly controlled simulation of both failed/partial flush and uncertain close, followed by owned numeric-FD reuse. It must not be described as reproduced interpreter finalization, ordinary flush-error behavior or an actual key-generation failure.
