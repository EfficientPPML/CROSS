# Qwen166 key-generation producer: proposed source selection

This is a source/public-metadata plan, not an implementation or execution grant. No producer/backend module was imported, no context or key was constructed, and no existing key, ciphertext, model, token, calibration or validation body was opened. `derive_public_plan.py` used only stdlib parsing/hashing and integer arithmetic over pinned public metadata and source text. All admitted 43/28/328/366 sources remain unchanged. The next implementation should be isolated, initially expose only a trusted recording seam, and leave the actual entry disabled.

The missing component is the retained-key producer behind the admitted Qwen43 readers. Existing core generation already has the required calls and shapes. The default125 and Toy4v4 wrappers cannot be copied wholesale: their profiles, candidate/checkpoint bindings, key counts and public/private schemas are BERT-specific; default125 generation also retains owning-fdopen/dup and ad hoc cleanup paths. Toy4v4 repaired those active generation operations, but its array authentication still lacks the later pre-read header cap. The selected Qwen43 reader and shared cleanup policy close that particular reader gap. The existing 28-file publisher supplies a reviewed descriptor/directory ownership pattern, not a directly reusable ciphertext serializer for keys.

1. **Fixed public contract and source closure.** Use the exact profile `2b2457e5…`, actual matrix key-plan `bac55deb…`, and candidate `344954b3…` already admitted by Qwen43/366. `public_plan.json` records the complete ordered Q100/P14 lists and literal 166 rotation indices, including 65535 and conjugation index 262143. Do not normalize, deduplicate by automorphism equivalence, omit either index, or substitute a BERT key ledger. The physical profile is N131072, slots65536, depth49, composite degree2, layout[256,512], precision32, dnum8 and canonical scale1.1467305003699405e18. The secret remains uniform ternary and sigma3.190000057220458984375. The static full QP bit length is3403 against the inclusive3523 ceiling; exact P-product415bits covers all eight Q partitions (maximum390bits). The actual selected `qp_is_secure` and `assert_p_coverage` predicates must also run before any RNG/key generation in a future authorized role. This plan does not claim their execution.

   `source_selection.json` pins all34 unchanged default125 core files, their exact copies already selected in366, eleven unchanged component candidates, twelve public metadata files and reference-only source files. Core `key_gen.py` remains742e6af9…. Keep existing package/bare-module aliases bound to the same selected bytes (`jaxite_word.key_gen`/`key_gen`, `rns`, `util`); reject preloaded foreign aliases and source drift before imports. Do not silently select installed fallback modules or source/provenance directories. The prior34-source assembly is a concrete dependency starting point, not a new actual-role bootstrap proof.

2. **Pre-generation intent versus post-generation identities.** Introduce a pure immutable `GenerationIntent` in the new producer module. It binds the full public contract, exact profile/key-plan/keygen/core source closure, independently supplied model_id, key-generation producer source-manifest identity, separately named request-producer and response-consumer identities, fresh public/private output roots, nonce and reviewed resource policy. The existing file identity's producer/consumer fields must retain their role meanings; the key producer's source identity needs its own explicit receipt field. Initial plan fields for actual grant, scientific freeze/heldout prerequisites and execution authorization remain absent/false, rather than fabricating receipts.

   Context_id and the public/private manifest digests cannot be supplied before random keys exist. After generation, derive exactly the existing Qwen schema: public_body plus `context_id=SHA256(canonical(public_body))`; private manifest binds that context and the exact public manifest hash. An independently authenticated terminal receipt and outer/root admission then bind those new hashes to the predeclared intent. Only that external admission supplies the current reader's `ExpectedIds`; the producer's own returned manifest is not its own authorization. No reader schema or `KEYGEN` constant needs to change for this producer.

3. **Exact cryptographic sequence and typed outputs.** Preserve core functions byte-for-byte, and preserve the existing wrapper call sequence: `gen_pke_pair(Q, [], N, noise_std=sigma)`, `gen_evaluation_key(secret, q=Q, P=P, dnum=8, noise_std=sigma)`, then one `gen_rotation_key(secret,Q,P,index,dnum=8,noise_std=sigma)` for each literal index in the fixed order. No optional deterministic sample inputs, seeded alternative, refreshed secret or separate per-key secret is selected. Keep the original Python-integer secret for evaluation/rotation generation; storing a uint32 copy must not replace that operand before its square/modular arithmetic. Check exact pair and switch-result inventories, ordered Q/P metadata, shape and every residue before storage conversion. `_array`, `_switch_metadata`, `_security_check`, `inventory` and `resources` have equal ASTs in default125/Toy4v4; their pinned ASTs are reusable where their global contract is explicitly supplied.

   Public storage has335 arrays: public_key.npy uint32[2,100,131072], relin_a/b and332 rotation a/b arrays uint32[8,114,131072]. Public inventory is those335 arrays plus public_manifest.json. Private inventory is exactly secret.npy uint32[100,131072] plus private_manifest.json, with0700 directory and0600 files. Both manifests remain the existing `cross-qwen-full-*-keys-v1` schemas; no BERT binding, request tile, result class count or ledger is carried over.

4. **New `qwen_key_store.py`, using reviewed ownership primitives.** Build a small key-specific retained writer, not a new generic publication framework. Reuse exact shared cleanup_origin4543, key_descriptor_io non-owning stream/hash/close policy, and the current shared Finalizer. Adapt the publisher's descriptor-before-open, held parent/root/file inode, same-fd readback, exclusive-create, short-write/error and detach-before-close behavior. The writer must exist before opening a file; the root owner must exist before creating its directory. Capture original owner/check/close callables and returned arrays in run-local ownership before callbacks or later factories. A setup failure must still retire every previously acquired original descriptor.

   Stream ordinary NPY output through a non-owning `closefd=False` stream on the retained exclusive O_RDWR descriptor, using the unchanged validated uint32 representation. Never transfer descriptor ownership to fdopen, duplicate descriptors for constructor handoff, or retry an uncertain close. Keep each original file inode and state through final readback. Compare held and named parent/root/file identity, exact header/extent/hash and residue bounds before manifest publication and before close. Use the Qwen43 bounded-header reader (512-byte pre-read cap) for readback or a minimal same-fd adaptation with that exact header semantics; do not reuse the older Toy4 parser as an arbitrary-header bound. Prefer one array at a time for generation/storage/readback; do not introduce a second full335-array in-memory inventory or convert all NPY bodies into one immutable bytes object.

   All335 public arrays and the private secret must be complete and authenticated before either completion manifest is declared successful. Write/readback/fsync the private manifest and then public manifest, fsync both directories and their retained parents, recheck complete directory inventories/permissions and source hashes, then attempt all original consumer/descriptor cleanup. Existing filename presence is not a commit marker; a manifest can exist after a late fsync/close failure. A chosen cleanup or ownership failure therefore prevents readiness. Retain partial owned directories as failed evidence; never delete replacements or borrowed paths and do not automatically reuse the failed generation. Secret/temporary owners remain quarantined on uncertain readiness until the dedicated process exits; no secure-memory-erasure guarantee is claimed. Public diagnostics contain bounded phase/count/error-class metadata, never key values or exception payload dumps.

5. **Storage and lifetime limits.** The public raw arrays total159,807,176,704bytes and the private array52,428,800bytes. Existing per-file NPY allowance4096bytes plus the inherited1GiB public/1MiB private reserve requires160,882,290,688bytes public and53,481,472bytes private (sum160,935,772,160bytes on a shared filesystem). These are logical file/capacity requirements, not peak RAM or generation/runtime performance. Future preflight must check the actual destination filesystem(s) before creating roots, using the sum on a shared device and independent capacities otherwise. Do not assume `/tmp` or any existing volume has this capacity. Holding all output files plus two root and two parent descriptors needs342 owned descriptors before bounded verification temporaries; the implementation must state its extra descriptor allowance and reject insufficient limits. Backend working buffers, Python secret representation, JIT/device resources and transient conversion/map space are excluded here and require a later resource grant.

6. **Terminal readiness is a separate gate.** A future dedicated keygen worker must enter only through external source-manifest/grant admission before helper/backend imports, validate protected/resolved root separation before output acquisition, and own its public report output. It must record generation/security/source/readback/fsync/cleanup completion as false until each actually finishes. Public receipt fields bind intent, exact source closure and keygen hash, profile/plan/checkpoint/config/candidate/model IDs, public/private manifest hashes, context_id, retained root identities, exact335/166 inventories and terminal result. The private directory remains private; sharing its manifest hash does not expose its body.

   Apply the already reviewed `terminal_status` boundary after argparse: only normal exact integer status is valid, and escaped BaseException—including post-report cleanup/SystemExit—maps to reserved infrastructure70. The supervising owner must directly wait/reap, check actual PID/group absence and source postchecks, and publish an independently pinned outer receipt. Root's final ready admission binds worker/parent reports, outer receipt, script/source/archive/grant hashes and output-root identities. A successful manifest write, reported boolean, absent stderr or process disappearance alone is insufficient. This plan selects no runnable worker/collector and issues no ready receipt. It also does not make a key store into candidate calibration, heldout, row0 or HE-accuracy evidence.

7. **Minimal next implementation and focused checks, after review.** Add only `qwen_key_producer.py` and `qwen_key_store.py` with small associated tests in a new successor. Keep the actual entry as immediate denial; `_generate_for_recording` may accept explicitly synthetic dependencies behind a trusted component seam. Test full166 call/order and335 descriptor schema with recording crypto outputs, including65535/262143 and missing/extra keys; verify original secret identity is passed to every key primitive. Exercise the writer on small newly owned NPY files with genuine header/hash/residue readback, fresh/aliased/replaced-root rejection, interrupted/short writes, fsync/close errors, original callable capture and same-body/cleanup-cancellation selection. Confirm both manifests are withheld as successful until the complete inventory and all retirement obligations pass. Test public/private canonical round-trip with the unchanged Qwen43 parser and externally supplied post-terminal expectations. These tests must label physical335 mapping/cryptography as recording seams, and must not allocate full genuine key bodies, import a backend, construct a context or claim generated-key compatibility from recording results alone.

No full inherited suite or actual keygen run is proposed before those concrete source changes and their new boundary tests are reviewed. The highest-impact gap is this Qwen-bound generation/store pair; expanding unrelated audit matrices or modifying core randomness, numerical parameters, decoder, full208 arithmetic or contestant starter would not close it.
