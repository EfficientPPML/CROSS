This is feasible as an explicit, short-lived same-input decomposition owner. It is not a drop-in use of the existing QP hoisted-rotation API. The inspected source is the frozen stage4-v2 closure; thirteen exact source files and the public integer inventory are archived. No numerical, HE, JAX, context or key operation was executed.

The ordinary generic HERot path performs key switch, QP-to-Q ModDown, c0 addition in Q, then the coefficient automorphism. The common sub-31-bit Barrett path fuses that same sequence, processing the two components separately and performing c0 addition only for component0. In contrast, `_hoisted_rotate_array` adds the P-scaled first component and applies the map in QP before a subsequent ModDown. That existing API must not replace these routing rotations when exact ordinary-path residues are the goal.

The reusable computation is already identifiable: `_prepare_decomposition_inputs` takes the same ciphertext c1 and computes its inverse NTT; `_decompose_part` performs each fixed partition's basis extension, NTT and tower restoration. Neither computation refers to a rotation key, index or map. `_decompose_array` exposes the resulting uint32 digits with shape `(parts,batch,1,r,c,Q_level+P)`. For each requested key, the logical completion can be expressed using existing kernels as `_key_switch_core_array(digits,a,b)`, `_mod_down_array`, `_add_first_component_array(...,original_input)`, then `_automorphism_array(...,map)`. No plaintext multiplication, cross-key sum, automorphism or c0 addition moves before that key's own ModDown.

Two implementation choices remain for a future isolated proof. The smallest arithmetic-reuse prototype composes those existing generic methods and compares every residue against the actual ordinary dispatch, including its fused Barrett path. The narrower production optimization would expose prepared digits to an extracted, otherwise unchanged fused Barrett completion body. Its digit products, increasing partition accumulation order, reductions, per-component ModDown, uint32 subtraction/addition and coefficient map must remain exactly as in `_rotate_barrett_fused`. Generic composition has different casts/strictification boundaries from that fused code even where Barrett canonicalization makes them algebraically redundant. Consequently this audit does not claim measured bit equality. Existing tests compare decomposed key switching for Montgomery and check decoded hoisted outputs, but do not establish this proposed exact completion against the production fused path for all required profiles/levels.

The useful caller boundary is a `rotate_same_input`/borrowed prepared-group operation at `CompiledRotation` and `CompiledArithmetic`, then the two routing `_stage` loops. Those loops currently apply every nonzero rotation to the identical `value`, and call weighted_sum only after all rotated values exist. Head stages have eleven nonzero rotations and local-key stages fifteen; the unchanged zero rotation must still return the input alias in its original list position. Keep the exact ordering, count, scale/NSD/layout, weighted-sum order and callbacks. Do not deduplicate duplicate output requests or share digits across a weighted sum, rescale, add, refresh, changed payload or second routing stage. The whole-key-tile rotation is a separate source and is not part of these groups. This optimization does not reduce the number of rotations, key products, ModDowns or model levels.
