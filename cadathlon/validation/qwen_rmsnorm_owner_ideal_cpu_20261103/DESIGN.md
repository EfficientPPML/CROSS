# Frozen candidate3 RMSNorm owner

Proposed API: `QwenRMSNorm(arithmetic, manifest_bytes, config_bytes, public_norm_bounds_bytes, *, site, gamma, positions, refresher=None, progress=None)`, then `evaluate_tile(ciphertext, tile=..., capture_checkpoints=False)`. It returns the output, original positions, actual metadata plan and optional variance/inverse checkpoints. Context and refresher are borrowed, serial and never closed by this owner. The initial supported input level is exactly25; extension to other levels must be explicit rather than silently changing the public continuation schedule.

`design.json` enumerates all113 frozen sites, exact gamma hashes, group widths, domains, selected degrees/iterations and inverse-only refresh placements from the already archived public continuation plan. Input/post/final sites normalize one1024-wide group per token row; Q/K sites normalize16 or8 independent128-wide groups. Each F4096 row retains its original public position. All inactive groups and rows get a fixed in-domain dummy variance; final gamma weights mask them to zero. No centering is introduced.

The variance circuit consumes two levels: square25→24, group sum, anchor mean/epsilon23, broadcast. The positive and negative power rotations require20 keys for1024 or14 for128 before the separate bootstrap union. Inactive padding is excluded at aligned anchors; inverse evaluation covers every physical slot on an active variance or the fixed dummy. Hostile padding tests are ideal algebra checks and do not bound its encrypted noise.

The36 polynomial sites use the exact original balanced Chebyshev map, every basis term and ordered final coefficients. No monomial conversion or pruning is introduced. The77 Newton sites retain the exact rounded first affine and15–24 original updates, each later update using square, variance product, correction(-.5,1.5) and estimate product. The retained source stays25 and variance23. Only inverse estimates are refreshed at the public schedule's260 events across one application of all113 sites, with each fixed event bound in1..64. Degree512 outputs at3 are refreshed before the final two operations. Output levels range2–23.

Every weighted stage uses the production binary64 ordering `s*((delta*D)/s)/D`; products use the actual ordered dropped pair, additions preserve the left metadata after compatibility checks. Remaining steps are replanned from each actual refresh scale, including adjacent-to-delta values. No nominal canonical assignment is allowed. Constructor/site/gamma/layout/helper/key/refresher identities and complete typed rule fields are bound before work; callbacks protect original source, variance, retained estimate/basis terms and captured checkpoints.

Implementation inputs are copied and hashed in `source_inventory.json`. The head owner's primitive metadata guards and the reviewed full-period refresh checks are reference code; the latter's BERT-only amplitude whitelist must be replaced in a NEW Qwen-specific binding by the exact site's allowed event bounds. The original files remain unchanged. The selected polynomial evaluator body is also pinned for equivalence checks. Runtime imports of crypto/security remain deferred to construction; the pure public contract can be imported without a backend.

This design reads only public metadata/source files. It does not load gamma tensors, model weights, calibration/fresh/held-out trajectories, native inputs, keys or ciphertexts. Constructor gamma authentication can be tested with an explicit synthetic fixture seam; a real pinned gamma-only fixture requires a separately scoped public parameter read. No model execution is needed for that eventual fixture.

Domain membership, shared-input variance and ideal coefficient certificates remain assumptions. Raw-input refresh bounds up to32768 and normalized-output bounds up to8192 are unresolved by inverse-only continuation. Actual p60 full-period refresh accuracy, propagated perturbations, all-layer composition, file handlers and performance remain separate requirements. No HE launch or encrypted-readiness claim is authorized here.
