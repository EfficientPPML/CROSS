## File lifecycle and reuse

Byte-exact reviewed BERT286/default125 source helpers will be copied only with explicit provenance. Reuse is limited to bounded descriptor I/O, ownership, payload-format validation, attempt-all cleanup and terminal process structure where compatible. Their BERT model/profile/key-count/request/response contracts are not reused. The new Qwen schemas must enumerate every field, reject unknown/type-aliased fields, and bind both producer and consumer identities.

Request uploads are borrowed read-only. Response and client completion/result roots are fresh owned disjoint roots. Each ordered artifact must authenticate before any backend wrapper is constructed; the client authenticates all38 payloads before opening its private loader. Server computation and all output readiness barriers finish before any private decode. No metadata publication can certify external wait/reap/group retirement; that requires an independent outer receipt.

Parameter mappings and key/context/compiled owners outlive all consumers and readiness barriers. An entered arithmetic or barrier failure quarantines the complete retained ownership graph until dedicated-process exit; ordinary file-reader failures attempt all safe releases and preserve the genuine body-primary object. Uncertain close resources are retained and never retried. Normal cleanup checks held identities, performs source/parameter readback, retires compiled owners before borrowed key mappings, and publishes completion only after cleanup and signal restoration. The initial component does not yet provide an executable HE process harness or assert process isolation.
