# Targeted client kernel-path source preparation

This is uncollected, unexecuted source. It does not authorize a subprocess,
metadata observation, capacity probe or actual client phase. A separate root
review and exact run grant remain required.

The selected runtime is the separate464 successor. Its sole overlay is
`qwen_client_dependencies.py`; the other463 files and runtime inventory are
exact predecessor bytes. `runtime/` retains that closed source tree. Tests and
their metadata live outside it. The unchanged old464 control is reconstructed
from those bytes plus the preserved old dependency file and exact old map.

Exactly24 cases are proposed in one new test file: three selected `_kernel`
reads of this dedicated child's status/cgroup/mountinfo, three direct builtin
audit-event reads of the same literal strings, seven disallowed flag cases,
eight disallowed spelling cases, and three old464 rejection controls. These
are six positive read cases and15 successor negatives plus three predecessor
controls. No prior preparation test is selected.

Each child authenticates its complete464 map before importing the actual pure
dependency module. It installs the actual AccessScope wrapper/audit hook using
explicit synthetic phase/profile/empty installed-code descriptors. Those
fixtures do not constitute ModelAdmission, GeneratedKeyReadiness, phase
authority, complete335 key inventory or resource admission. No actual entry,
full process, `check_capacity`, cgroup byte read, backend import or context is
selected. A fresh backend import gate forbids NumPy/JAX/core/model packages.

The proposed reads are limited to `/proc/self/status`, `/proc/self/cgroup` and
`/proc/self/mountinfo` of the dedicated child. Contents and hashes are not
published; only bounded nonempty-read and policy results are recorded. Denied
open cases do not perform a body read or write even if unexpectedly admitted:
the descriptor is closed once and the case fails. One fresh owned scratch
directory and symlink exist only to exercise alias rejection. Existing
model/key/token/ciphertext/private files are never consulted.

The wrapper retains the original `os.open` argument. Exact bytes/PathLike,
noncanonical spelling and dir_fd negatives therefore exercise that wrapper.
Direct builtin `open` audit events can attest only their observed normalized
string; the tests do not claim recovery of the caller's pre-normalized type.
Generic canonical-path checks remain unchanged for every other path. Explicit
`/proc/<pid>/status`, another self leaf and the owned symlink remain denied.

Every case checks sticky denial or an empty denial list, original `os.open`
restoration and audit deactivation. The parent owns direct child wait/reap and
group-absence checks; all post-Popen work is within ownership cleanup. There is
no healthy-child deadline. Source equality is checked before/after. This narrow
proof would close the startup audit/path mismatch only; it cannot establish
installed backend import readiness, actual memory/storage capacity, any client
role outcome or numerical correctness.
